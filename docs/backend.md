# Сервер и панель преподавателя

Сервер на Node.js 22.5+ без внешних зависимостей: встроенный `node:sqlite`, `node:http`, `crypto.scrypt`. Код в папке `server/`, интерфейс панели в `src/admin/`.

## Запуск

```bash
npm run build
npm run server
```

Сайт откроется по адресу `http://127.0.0.1:3000/tz-praktik/`, панель: `#/admin`. При первом запуске создаётся администратор `admin`. Пароль берётся из `ADMIN_PASSWORD` или генерируется и печатается в консоли один раз; смените его в панели («Аккаунт»).

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT`, `HOST` | `3000`, `127.0.0.1` | Адрес. Чтобы открыть сервер в сети, задайте `HOST=0.0.0.0` и поставьте перед ним HTTPS-прокси |
| `DB_PATH` | `data/tz-praktik.db` | Файл SQLite (в `.gitignore`) |
| `ADMIN_USER`, `ADMIN_PASSWORD` | `admin`, случайный | Первый администратор |
| `COOKIE_SECURE` | выкл. | `1` — cookie только по HTTPS (включается сам при `X-Forwarded-Proto: https`) |
| `PUBLIC_ORIGIN` | `*` | Откуда студенты могут отправлять попытки (CORS), например `https://qroka.github.io` |
| `SESSION_DAYS` | `7` | Срок сессии администратора |

Администраторами можно управлять и из консоли: `npm run server:admin -- create <логин> <пароль>`, `password <логин> <пароль>`, `list`.

В разработке: `npm run server` в одном терминале и `npm run dev` в другом (Vite проксирует `/api`).

## Что делает панель

- **Обзор.** Попытки, студенты, средний балл и медиана, время, распределение оценок, попытки по дням, средние баллы по критериям, сведения, которые студенты выясняют хуже всего, частые штрафы.
- **Сценарии.** Загрузка файла `scenariy.json` (проверка и распознавание вопросов выполняются в браузере до загрузки), выбор текущего сценария для студентов, настройки (название, описание, время занятия, заметка), скачивание файла, удаление.
- **Студенты.** Аккаунты студентов: ФИО, группа, личный код. Добавление, список группой, правка, новый код, коды для печати. Подробности ниже.
- **Ответы студентов.** Список с поиском, **фильтром по группе** и другими фильтрами, сортировкой и страницами; карточка попытки: итог, переписка, реестр, текст ТЗ; отчёт по попытке; удаление.
- **Обратная связь.** Лайки и дизлайки студентов на ответы заказчика: счётчики, темы ответов с наибольшим числом дизлайков (с чего начинать правку сценария), список оценок с вопросом студента, ответом, пояснением и ссылкой на всю переписку. Фильтры по сценарию, оценке и тексту.
- **Отчёты.** Таблица Excel (.xlsx) по попыткам с фильтром по сценарию и группе, с колонкой «Группа»: время в московском часовом поясе, закреплённый заголовок, автофильтр и Markdown-отчёт по сценарию.

## Как студенты попадают в базу

Страница студента при открытии запрашивает у сервера текущий сценарий. Если сервер отвечает, студент входит в личный кабинет, а его попытка сохраняется на сервере через 6 секунд после последнего изменения и сразу при завершении. Если сервера нет, сайт работает как раньше, ничего не отправляя.

Можно держать сайт на GitHub Pages, а сервер отдельно: соберите сайт с `VITE_API_URL=https://адрес-сервера/api` и задайте `PUBLIC_ORIGIN`.

## Личный кабинет студента

При подключённом сервере сайт сначала просит войти. Без сервера (например, на GitHub Pages) всё работает как раньше: имя и локальное хранение.

**Регистрация.** Студент один раз указывает ФИО (фамилия и имя полностью) и группу и получает **личный код из четырёх русских слов**, например `мрамор-дуб-фрукт-табурет`. Группу можно выбрать из подсказки: написание берётся то, которое уже встречалось («ис-21» и «ИС-21» — одна группа). Один и тот же студент в одной группе не регистрируется дважды.

**Вход.** По коду, с любого устройства: регистр, пробелы вместо дефисов и «е» вместо «ё» не важны. На общем компьютере «Выйти из аккаунта» сохраняет попытку на сервере и убирает всё с этого компьютера.

**Кабинет.** ФИО, группа, код (копируется), кнопка «Продолжить» для незавершённой попытки, «Начать новую попытку» (по сценарию, который сейчас выбран преподавателем) и история всех попыток: дата, сценарий, число вопросов, результат. Завершённую попытку можно открыть и посмотреть результат, незавершённую продолжить. Из рабочего экрана в кабинет ведёт пункт «Личный кабинет».

**Потерял код.** Преподаватель выдаёт новый в разделе «Студенты»: старый перестаёт работать, а все входы студента на других устройствах закрываются. Попытки сохраняются.

**Сменили сценарий, пока попытка шла.** Старые попытки продолжаются по своему сценарию; новые попытки идут по текущему.

**Работа с двух устройств сразу.** У каждой попытки на сервере есть номер версии. Если другое устройство успело сохранить свою версию, сайт не затирает её молча, а показывает диалог: «Загрузить версию с другого устройства» или «Оставить мою версию». Закрыть диалог мимо кнопок нельзя.

**Что было до кабинета.** При обновлении базы для каждого имени из уже сохранённых попыток создан студент без группы, а его код равен коду последней попытки: выданные раньше коды продолжают работать как вход в кабинет. Группы проставьте в разделе «Студенты».

### Раздел «Студенты» в панели

- Список с поиском (ФИО, группа или код, без учёта регистра и «ё»), сортировкой и **фильтром по группе**. Для каждого студента: код, число попыток, лучший балл, последняя попытка и последний вход.
- **Добавить** одного студента или **списком**: строки «ФИО; группа» (разделитель `;`, запятая или табуляция), группа по умолчанию для строк без неё. Результат показывает выданные коды и причины пропуска строк (дубль, нет фамилии и имени).
- **Изменить** ФИО и группу: новые значения попадают и в уже сохранённые попытки. **Выдать новый код**, **удалить** (с попытками только после подтверждения).
- **Коды (XLSX)**: ФИО, группа и код для печати и раздачи, с учётом выбранной группы.
- Фильтр по группе есть также в «Обзоре», «Ответах студентов» и «Отчётах»; в таблицу попыток добавлена колонка «Группа».

Сайту студента сервер выдаёт токен сессии (180 дней), он хранится в браузере и передаётся в заголовке `Authorization`, поэтому сайт может стоять на другом адресе, чем сервер.

## Безопасность

- Пароли хранятся как scrypt-хэши; сессии — случайные токены, в базе только их SHA-256; cookie `HttpOnly`, `SameSite=Lax`.
- Вход ограничен 8 попытками за 10 минут с одного адреса; неверный логин и неверный пароль неотличимы.
- Изменения в админском API требуют заголовка `X-Requested-With: tzp` (защита от CSRF); CORS открыт только для `/api/public`.
- Лимиты: 3 МБ на попытку, 5 МБ на файл сценария, 240 отправок в минуту с адреса.
- Регистрация открыта: кто знает адрес сервера, может зарегистрироваться (не больше 20 регистраций в час с одного адреса). Кабинет и попытки доступны только по токену студента: чужую попытку открыть или изменить нельзя, это проверяет сервер. Имя и группа в попытке всегда берутся из аккаунта.
- Код из четырёх слов даёт около 33 бит случайности. Подбор ограничен: 40 попыток входа за 10 минут с одного адреса, неверный и несуществующий код неотличимы. Кто знает код студента, может войти как он: просите не передавать его другим. Самостоятельную регистрацию отключить пока нельзя.

## Резервная копия

Вся база — один файл `data/tz-praktik.db` (рядом могут лежать `-wal` и `-shm`). Копируйте его при остановленном сервере.
